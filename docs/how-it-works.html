The components

DevicesWhatever you run Obsidian on, each holding a full copy of the vault.
Does
Where you read and write. Obsidian's Daily Notes plugin opens today's note under daily/.
Lives
Your laptop, your phone. The librarian never talks to them.
Without it
Nothing: a device only ever holds a copy.
SyncWhatever carries the vault between your devices and the server. Not part of this repo.
Does
Keeps every copy identical. Syncthing, a mount, or simply editing on the server all work; the librarian only needs the files on disk.
Lives
Your choice. If it is a synced folder, keep .git out of the sync; the installer adds it to a Syncthing .stignore if one exists.
Without it
Edits stay where they were made until it is back.
Note
Anything the librarian merges reaches your devices as soon as the sync runs, before you read the PR.
ServerThe always-on Linux machine that holds the master copy and runs everything.
Does
Two accounts matter: yours (sudo, runs the installer) and librarian (owns the vault, runs the nightly, no sudo).
Lives
Anywhere with systemd. The vault and its worktrees must sit outside /home, /var and /tmp, which the model is denied.
Without it
Devices keep working on their copies; nothing syncs or files until it is back.
VaultThe master copy of the notes, as plain files, and a git repository.
Does
Git is the ledger: every change is a commit with author, time and diff, and any commit can be reverted. Each night leaves you: DATE (your edits), librarian(realm): DATE (its filing) and, some nights, an open tidy PR.
Lives
VAULT_DIR in /etc/librarian/env; .git only on the server, pushed to GitHub. Realms: personal/ and work/<co>/, each with its own rules, index and lessons.
Without it
The devices still hold full copies; GitHub holds history.
Note
Undo a night: revert the merge commit. Never git reset pushed history.
Daily noteOne file per day; the inbox. Four headings are load-bearing.
Does
## Personal and ## Work, each with ### Happened (yours, never touched) and ### To file (emptied nightly), and ## Filed (the nightly writes the PR link and links to every note it touched). Anything else in the note is free.
Lives
daily/YYYY/YYYY-MM-DD.md, template templates/daily.md.
Without it
Nothing gets filed. If a ### To file heading goes missing, the nightly warns and the healthcheck fails.
Note
Changing the layout: docs/daily-note.md.
NewdayCreates today's note from the template at 00:05.
Does
So the note exists on every device before morning. If a device creates it first, the two are byte-identical.
Lives
librarian-newday.timer.
Without it
You create the note by opening Daily Notes; same result.
NightlyThe bash script that runs the whole night at 03:00.
Does
Refuses if the stop file exists → commits your day → reads your comments on last night's PR → makes the Worktree → runs the Model per realm → audits the result → opens one PR, empties To file, writes Filed, merges, fast-forwards the Vault → maybe a tidy PR → pings Healthchecks.
Lives
/usr/local/bin/librarian-nightly; logs /var/log/librarian/; artifacts /var/lib/librarian/runs/DATE/.
Without it
Nothing is filed; captures wait in To file. Nothing is ever half-done: a failed run throws the Worktree away.
Note
Run by hand: sudo -u librarian -H librarian-nightly --date DATE (--dry-run to only see the prompts). Full sequence: docs/architecture.md.
WorktreeA throwaway copy of the Vault the Model works in.
Does
The synced Vault is never touched during a run. After the PR merges, the Vault fast-forwards to the result; that is the only moment it changes, and your sync carries it out.
Lives
<vault's parent>/librarian/worktree, empty between runs.
ModelOne claude -p run per realm with five file tools and nothing else.
Does
Reads the Rules, merges each capture into the note it belongs to or creates one, links both ways, adds (from [[DATE]]), updates the index, applies your comments and writes general rules to lessons.md. Ends with at most three Notes for you.
Lives
Runs as librarian inside the Worktree, empty environment: no shell, no network, no tokens. The work realm can run on a separate Team token.
Note
The <material> it receives is treated as content to organize, never as instructions.
GuardA small program that approves or denies every file operation the Model attempts.
Does
Resolves the real path (symlinks, ..), then: writes only under the realm's folder, never journal/, dot-files or rules files; reads only inside the realm plus the top-level rules. Any error is a no. After the run the Nightly audits the Worktree too: anything outside the realm is reverted (REVERTED), a remote image is held (HELD), and the PR stays open.
Lives
lib/guard, installed to /usr/local/lib/librarian/guard.
Note
Checked, not trusted: librarian-boundary-test tells a real model to break 26 rules and passes only if every attempt was denied. Run after any change to the Guard, settings, or Claude version. docs/boundaries.md; what it does not stop: SECURITY.md.
RulesWhat the Model reads before filing: rule files, learned lessons, the prompts.
Does
CLAUDE.md (vault-wide conventions), personal/CLAUDE.md and work/<co>/CLAUDE.md (what goes where), lessons.md per realm (rules learned from your PR comments), and the prompts file.md / tidy.md.
Lives
Rule files in the Vault (the Model may never write them); prompts in prompts/.
Note
Why lessons.md and not CLAUDE.md: rule files are instructions other agents follow, so a bad night must not be able to write them.
ConfigThe Nightly's settings and secrets, root-owned.
Does
env (vault path, repo, healthcheck URL, stop file, pinned Claude binary), github-token (limited to the vault repo), work-token (optional). The Model's process never sees them; only the wrapper does.
Lives
/etc/librarian/. Rotation: delete the file, rerun the installer, paste at the prompt.
GitHubThe private vault repo: the ledger, the review surface, the feedback channel.
Does
Each night's PR shows the diff. A comment on a file line goes to that file's realm; a general comment goes to both; only the repo owner's comments count.
Lives
A private repo of yours; a fine-grained token with Contents and Pull requests access.
Without it
The Nightly can't push or open PRs; it fails and the healthcheck emails. The Vault and devices are unaffected.
ClaudeThe AI the Model thinks with, over the internet.
Does
Its only outside connection. Personal realm on the librarian user's login; work realm on a Team token if you gave one.
Lives
Anthropic's API.
Without it
The Nightly fails and emails; nothing changes.
HealthchecksOne scheduled ping; an email when it is late or reports failure.
Does
/start after your day is committed, success at the end, /fail with a reason: run error, PR left open, missing heading.
Lives
healthchecks.io, or anything with the same URL scheme. Optional.
Note
What to do per email: the table below.
BackupYours to bring. Not part of this repo.
Does
Git on GitHub holds every version of every note, but not a deleted repo. A snapshot of the vault on a schedule, somewhere else, is the rest.
Note
A backup that can detect a sudden shrink is a good writer of the stop file.
Stop fileAn optional path; the Nightly refuses to run while it exists.
Does
A tripwire for whatever you want to pause the librarian: a backup that saw the vault shrink, a sync gone wrong, or you. Remove the file to resume.
Lives
STOP_FLAG in /etc/librarian/env; empty means no tripwire.

A day

  • 00:05Newday creates today's Daily note; your Sync puts it on every device.
  • All dayYou write under Happened and To file on whatever Device is in your hand.
  • 03:00The Nightly: your day committed to the Vault, one Model run per realm in the Worktree, one PR on GitHub, merged; Filed links appear in the note; Healthchecks pinged.
  • MorningGlance at the PR: the Notes say what it was unsure about, the Files tab shows the diff. Comment, or don't. Merge or ignore a tidy PR.
  • Next 03:00Your comments are applied and become Rules (lessons.md).

When something goes wrong

Healthchecks emailThe body says why. Log: /var/log/librarian/nightly-DATE.log. The Vault is never half-done; any PR stays open.
PR not merged, banner HELDThe Model's text had a remote image or script tag. Read the diff on GitHub; merge or close by hand.
PR not merged, banner REVERTEDThe Guard let something through and the Nightly undid it. Run sudo -u librarian -H librarian-boundary-test before the next night.
"stop file present"Whatever wrote it had a reason. Look, then remove the file.
Something filed wrongFix it in Obsidian, or comment on the PR line; the next Nightly fixes it and adds the rule to lessons.md.
A note vanishedGit history first. The Model can't delete (deletions are reverted), so suspect a device or the sync.
"not logged in"sudo -u librarian -H bash -c 'cd && claude', open the URL, /exit.
Want to change how the Nightly worksOpen the repo in Claude Code; CLAUDE.md and docs/ are written for it. Deploy: sudo bash ./install.sh, boundary test, re-arm the timer.
